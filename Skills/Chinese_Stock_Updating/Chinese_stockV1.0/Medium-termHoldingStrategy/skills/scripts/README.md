# 持仓监控 · 每日条件单止盈止损（需求 5）

`daily_stop_plan.py` 记录已买入的持仓，并按**大盘/板块行情动态**给出
可直接填入券商 APP 的条件单参数。

## 与原有 stop_loss_engine 的区别

| | stop_loss_engine（原有） | daily_stop_plan（新增） |
|:---|:---|:---|
| 输出 | 建议动作（文字） | **券商 APP 可直接填的条件单参数** |
| 参数 | 固定 | **随大盘/板块 phase 动态调整** |
| 用途 | 人工判断 | 无人值守 |

## ⚠️ 回测结论：动态调整更差，默认已改为固定参数

131 笔实测（已应用大盘交易开关，T+10，止盈用回落卖出）：

| 方案 | 胜率 | 均值 | 中位 | 盈亏比 | 回撤 | 训练 | 测试 |
|:---|---:|---:|---:|---:|---:|---:|---:|
| **固定 -8% / 回落12%（当前默认）** | 54.2% | **+4.04%** | **+1.21%** | **2.07** | **-60.7** | **+5.90%** | **+2.21%** |
| 只按 phase 调止损 | 54.2% | +4.04% | +1.21% | 2.07 | -60.7 | — | — |
| 只按 phase 调回落 | 53.4% | +2.98% | +0.57% | 1.83 | -57.1 | — | — |
| 只加保本止损 | 58.8% | +3.44% | +0.20% | 1.67 | -64.3 | — | — |
| 三项全开（原动态默认） | 58.8% | +2.60% | +0.20% | 1.43 | -65.1 | +3.97% | +1.24% |

**两个原因**：

1. 应用大盘交易开关后，**只有 RANGE(127 笔) 与 STRONG_UP(4 笔) 能开仓**，
   "按 phase 调整"几乎没有施展空间；而 RANGE 把回落从 12% 收到 10% 是净损失（-1.06pp）。
2. **保本止损提高胜率（54.2%→58.8%）但降低期望（+4.04%→+3.44%）**——
   与前几轮一致的规律：保护本金会同时砍掉右尾。

**因此默认值已改为回测最优的固定参数**：

```python
DYNAMIC_BY_PHASE = False      # True = 按 phase 动态调整宽紧
BREAKEVEN_ENABLED = False     # True = 启用保本止损（胜率↑、期望↓）
```

需要"高胜率优先"时把 `BREAKEVEN_ENABLED` 打开即可（+4.6pp 胜率，代价 -0.6pp 期望）。

## 动态规则（DYNAMIC_BY_PHASE=True 时生效）

```
最终止损 = max(成本止损, 保本线(若曾浮盈达标), 最高价 x (1-回落比例))
```

| 大盘/板块 phase | 成本止损 | 回落比例 | 保本触发 |
|:---|---:|---:|---:|
| STRONG_UP（单边上行） | 10% | 15% | 峰值浮盈 10% |
| WAVE_UP（波段） | 9% | 12% | 8% |
| RANGE（震荡） | 8% | 10% | 6% |
| STRONG_DOWN / WEAK_DOWN | **5%** | **6%** | 3% |
| UNKNOWN | 6% | 8% | 4% |

**单边下行时自动收紧**（保护本金），单边上行时自动放宽（让利润奔跑）。

> 注：该机制已实现并保留开关，但**实测在本样本上不划算**（见上方回测）。

## 关键设计：保本看「峰值浮盈」而不是「当前浮盈」

实现初期曾出现一个荒谬结果：某持仓浮盈一度 +13%，回落后给出的止盈价却是
**低于成本**的 33.32（触发时反而亏 3.59%）。原因是保本判断用了当前浮盈。

修正后：只要**持仓期最高浮盈**达到过保本线，止损就抬到成本之上（+0.2% 缓冲，覆盖手续费）。

```
中国船舶   STRONG_UP   成本34.56 峰值浮盈13.43% 保本已武装 -> 保本止损 @ 34.63 (+0.2%)
半导体ETF  STRONG_DOWN 成本1.20  峰值浮盈 4.17% 保本已武装 -> 保本止损 @ 1.20  (+0.2%)
从未浮盈    RANGE      成本10.00 峰值浮盈 1.00% 未武装     -> 成本止损 @ 9.20  (-8.0%)
```
