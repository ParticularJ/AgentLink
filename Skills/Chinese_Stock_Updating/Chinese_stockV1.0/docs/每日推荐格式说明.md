# 每日推荐格式说明（收盘后运行 → 当晚检查 → 次日条件单）

> 适用时段：**CLOSE**（15:00 之后）。当日 K 线已定型，数据完整。
> 运行命令：`bash run_close_fusion.sh`（等价于 `fusion_runner.py --session CLOSE`）
> 输出文件：`recommendations/YYYYMMDD_CLOSE_BUY_recommendation.json`

---

## 一、一天的节奏

| 时间 | 动作 | 产出 |
|:---|:---|:---|
| 15:00 收盘 | 行情定格 | — |
| **15:05** | 运行 `run_close_fusion.sh` | 推荐 JSON + 卡片 |
| **当晚** | 你检查推荐，筛选要做的 | 定稿买入清单 |
| **当晚** | 照 JSON 在券商 APP 填智能条件单 | 买入单 + 止盈止损单 |
| **次日开盘** | 条件单自动执行 | 成交 / 未到价放弃 |

**关键设计**：推荐给出的是**计划**，不是"现在就买"。买入触发价 = 信号日收盘价，次日开盘高于它 5% 就放弃（不追高）。

---

## 二、推荐 JSON 的顶层结构

```json
{
  "date": "20261002",
  "session": "CLOSE_BUY",
  "generated_at": "2026-10-02T15:07:12",
  "market_phase": "RANGE",
  "market_phase_label": "震荡",
  "position_cap": 0.5,
  "trade_switch": "…仅在 RANGE/WAVE_UP/STRONG_UP 时开仓；否则写空推荐…",
  "sector_filter": { "sector_phases": {...}, "block": [...], "reserve_count": 0 },
  "recommendations": [ ...见下... ],
  "total_position": 37.0,
  "stock_count": 2
}
```

**大盘不允许开仓时**（STRONG_DOWN / WEAK_DOWN / UNKNOWN），`recommendations` 为空数组，
并在日志里打印 `🛑 大盘趋势禁止开仓`。**这一天就不要下单。**

```json
  "exit_plan": { "...旧字段，保留兼容..." },
  "target_reason": "…买入理由…"

```

### 字段含义速查

| 字段 | 含义 | 怎么用 |
|:---|:---|:---|
| `combined_score` | 融合综合分（0~100） | 参考，**不要只看它**——实测与未来收益 IC 为负 |
| `entry_quality` | **入场质量分**（越高越好） | 衡量这个点位好不好：不追高、不过热、有趋势、有资金 |
| `position_pct` | 建议仓位（占总资金 %） | 直接用于计算买入股数 |
| `entry_ref_price` | 信号日收盘价 | 条件单的**监控价** |
| `conditional_orders.buy.monitor_price` | 买入触发价 | 填券商"定价买入"的**监控价** |
| `conditional_orders.buy.order_type` | 限价委托 | 选"限价" |
| `conditional_orders.buy.valid_months` | 有效期 6 个月 | 选"长期有效" |
| `sell.stop_loss.trigger_price` | 止损价 | 填"止盈止损"的**止损触发价** |
| `sell.stop_loss.order_type` | 市价委托 | **止损一定选市价**（保命） |
| `sell.trailing.giveback_pct` | 回落 12% | 填"回落卖出"的**累计回落** |
| `sell.trailing.activate_price` | 激活价 | 填"回落卖出"的**监控价** |
| `execution.entry_max_price` | 最高可买价 | **开盘价高于它就放弃** |
| `execution.max_hold_days` | 最长持有 10 个交易日 | 到期人工了结 |

## 四、照着填券商 APP（以涨乐财富通为例）

每只推荐要设**两张条件单**，它们独立运行：

### 第一张：买入条件单

| APP 选项 | 填什么 |
|:---|:---|
| 功能 | 交易 → 智能条件单 → **定价买入** |
| 监控价 | `conditional_orders.buy.monitor_price`（= 信号日收盘价） |
| 委托价 | 同监控价（限价） |
| 委托数量 | `position_pct` × 总资金 ÷ 监控价，取整到 100 股 |
| 截止时间 | 长期有效（建议 3~6 个月） |

### 第二张：止盈止损条件单

| APP 选项 | 填什么 |
|:---|:---|
| 功能 | 智能条件单 → **止盈止损** |
| 基准价 | `sell.stop_loss.base_price`（= 你的成本价） |
| 止损条件 | `sell.stop_loss.trigger_price`（−8%）→ 委托方式选**市价** |
| 止盈条件 | 见下方"关于止盈" |
| 附加 | 再设一张 **回落卖出**：监控价 `trailing.activate_price`，累计回落 `trailing.giveback_pct` |

### ⚠️ 关于止盈：默认只有"回落卖出"，没有固定止盈价

**实测结论**：固定止盈会降低期望（707 笔样本，训练/测试两半都更差），
因为它截断了右尾。所以默认用"**回落卖出**"——涨过激活价后追踪最高点，
回落 12% 就卖，等效于"让利润奔跑"的止盈。

**如果你坚持要固定止盈点**（PDF 的"止盈 = 2×止损"），改一个常量即可：

```python
# fusion_config.py
CO_TAKE_PROFIT_PCT = 0.16    # 16% 止盈 / 8% 止损 = 2:1
```

改完后输出会多一个 `sell.take_profit` 块（限价委托），照填即可。

## 五、晚上检查推荐的清单

1. **看大盘**：日志里有 `🛑 大盘趋势禁止开仓` → **今晚不下任何单**。
2. **看条数**：正常 0~2 条。0 条也是正常结果，不要勉强。
3. **看入场质量分**：优先做分高的；分特别低的（接近当日阈值）可以跳过。
4. **看仓位**：`position_pct` 是建议值，按你的总资金换算股数。
5. **算总仓位**：`total_position` 已给出合计，别超过你的风险预算。
6. **次日开盘**：如果开盘价 > `entry_max_price`，**主动撤掉买入单**（防追高）。

## 六、持仓监控（次日之后的每天）

买入后，每天收盘后另跑一个脚本，它会**按大盘/板块行情动态**给出条件单：

```bash
bash run_position_plan.sh
```

输出每只持仓的：

```json
{
  "code": "600150", "name": "中国船舶",
  "market_phase": "RANGE", "profit_pct": 9.95, "peak_profit_pct": 13.43,
  "sell_order": {
    "type": "回落卖出", "trigger_price": 33.32, "trigger_reason": "回落卖出",
    "order_type": "市价委托(最优五档)", "pnl_at_trigger_pct": -3.59
  },
  "trailing": { "activate_above_pct": 10.0, "giveback_pct": 15.0 }
}
```

**重要规则**：只要持仓**曾经**浮盈达到过保本线，止损就会抬到成本之上
（避免"浮盈 13% 却跌回亏损才卖"）。这条逻辑已修好并有回归测试。

> ⏳ 待办：动态调整与保本在实际回测中**会降低期望**（+4.04% → +2.60%），
> 因此默认参数是**固定 −8% / 回落 12%**，`DYNAMIC_BY_PHASE` 与 `BREAKEVEN_ENABLED` 默认关闭。

## 八、已知的坑

1. **`entry_quality` 可能为 `null`** —— 取不到日线时放行，不误杀。若某天大量为 null，说明数据源异常。
2. **`combined_score` 的可信度低** —— 实测与未来收益秩相关为 **−0.052**（反向）。真正的过滤依据是 `entry_quality`。
3. **权重与阈值是本样本经验值** —— 样本外（尤其熊市）需要重新校准。
4. **触发 ≠ 成交** —— 跳空、跌停封死时条件单可能无法成交，这是系统性风险。
